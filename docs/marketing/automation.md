# Property OS — Αυτοματισμός Email (Runbook)

> Απάντηση σε μία γραμμή: **ναι, το σύστημα ξέρει τι στέλνει, σε ποιον και πότε.**
> Το περιεχόμενο (101 emails) και η μηχανή αποστολής είναι έτοιμα· η ζωντανή
> αποστολή ενεργοποιείται μόλις επιβεβαιωθεί το domain στο Resend.

## 1. Πώς αποφασίζεται τι στέλνεται και πότε

Τρία επίπεδα αυτοματισμού, κανένα χειροκίνητο βήμα στη ροή:

| Επίπεδο | Μηχανισμός | Παράδειγμα |
|---|---|---|
| **Χρονοπρογραμματισμένα** | `pg_cron` → `net.http_post` → `send-lifecycle-email` | μηνιαία κατάσταση (1η του μήνα), εβδομαδιαία επιτόκια, εποχικές καμπάνιες |
| **Event-triggered** | DB trigger / app event → `send-lifecycle-email` με `copyId` | καλωσόρισμα (εγγραφή), απόδειξη (πληρωμή), λήξη μίσθωσης (ημερομηνία), ληξιπρόθεσμο (dunning) |
| **Auto-reply (inbound)** | Resend inbound webhook → `reply_ack` | ο χρήστης απαντά σε email μας → αυτόματη επιβεβαίωση παραλαβής |

Ο κοινός δρόμος: **μία function** (`send-lifecycle-email`) δέχεται `copyId` + παραλήπτη
+ `params` εξατομίκευσης, επιλέγει το κείμενο από το `emailCopy.CATALOG` και στέλνει
μέσω Resend. Αυθεντικοποίηση zero-config μέσω `cron_secrets`.

## 2. Χάρτης αυτοματισμού ανά πρόγραμμα

| Πρόγραμμα | Έναυσμα | Χρονισμός | Μηχανισμός |
|---|---|---|---|
| Onboarding | Εγγραφή | Ημέρες 0 έως 14 | event + drip cron |
| Engagement | Περιοδικό / εισπράξεις | 1η μήνα, εβδομαδιαία | cron |
| Upsell | Όριο / δοκιμή | Με το συμβάν | event |
| Εποχικά | Ημερολόγιο | Ημερομηνίες καμπανιών | cron |
| Συστάσεις | Ενέργεια σύστασης | Με το συμβάν | event |
| Lifecycle | Συμβάν λογαριασμού / απάντηση | Άμεσα | event + inbound webhook |
| Win-back | Αδράνεια | Ημέρες 30 / 60 / 90 | cron (last_seen) |
| Λειτουργικά | Ημερομηνίες ακινήτου | Χ ημέρες πριν τη λήξη | cron (ημερολόγιο) |
| Βραχυχρόνια | Κρατήσεις | Ημέρα άφιξης/αναχώρησης | event (iCal sync) |
| Προϊόν | Κυκλοφορίες | Με την κυκλοφορία | ημι-αυτόματο (broadcast) |
| Μετατροπή | Αποδεδειγμένη αξία | Με το συμβάν | event |
| Συμμόρφωση | Προθεσμία | Πριν την προθεσμία | cron (φορ. ημερολόγιο) |
| Συνδρομή | Κατάσταση κάρτας | Πριν/μετά χρέωση | event (webhook εμπόρου) |
| Σχέσεις | Ενοικιαστής/συνιδιοκτήτης | Με το συμβάν | event |
| Αξία | Ευκαιρία (κατανάλωση, επιτόκια) | Όταν εντοπίζεται | event/cron |

## 3. Auto-reply (όταν μας απαντούν)

Ροή: εισερχόμενο email → **Resend inbound webhook** → η function ελέγχει ότι είναι
γνήσια απάντηση χρήστη → στέλνει το `reply_ack`:

> «Λάβαμε το μήνυμά σου. Ένα μέλος της ομάδας μας θα το δει και θα σου απαντήσει,
> συνήθως εντός μίας εργάσιμης ημέρας.» + παραπομπή στον βοηθό για το επείγον.

Κανόνες: μία αυτόματη επιβεβαίωση ανά νήμα (όχι βρόχοι), όχι σε no-reply, όχι σε
αυτόματα μηνύματα τρίτων. Το `reply_ack` είναι συναλλακτικό (χωρίς απεγγραφή).

## 4. Διακυβέρνηση (να μη γίνουμε spam)

- **Frequency cap:** το πολύ ένα marketing email ανά 3 με 4 μέρες/χρήστη· τα
  συναλλακτικά/λειτουργικά εξαιρούνται (τα ζητά το ίδιο το δεδομένο του χρήστη).
- **Suppression:** καθολική απεγγραφή από marketing, σεβαστή παντού· ξεχωριστός
  διακόπτης για τις λειτουργικές υπενθυμίσεις.
- **Ώρες ησυχίας:** αποφυγή αργά το βράδυ.
- **Προτεραιότητα:** αν πληρούνται πολλά εναύσματα, φεύγει το πιο σχετικό/επείγον.

## 5. Κατάσταση

- **Live:** μηχανή (`send-lifecycle-email`), 101 κείμενα, cron backbone
  (`email_marketing_cron`, `monthly_statements_cron`), `cron_secrets` auth.
- **Pending domain:** `RESEND_FROM` (branded αποστολέας), verify Resend, inbound
  webhook για το `reply_ack`, και οι per-event DB triggers που λείπουν.
- **Επόμενο:** σύνδεση κάθε εναύσματος (πίνακας §2) με DB trigger/edge function,
  ώστε να «ανάβει» μόνο του με το συμβάν του χρήστη.
