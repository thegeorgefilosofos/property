# Το lint debt των 429 `any` — αιτία και η μία διόρθωση

**Κατάσταση:** εντοπισμένο, όχι διορθωμένο. Απαιτεί ένα βήμα που χρειάζεται
διαπιστευτήρια βάσης, άρα δεν μπορεί να γίνει από αυτόματο agent.

## Τι δείχνει ο ratchet

Στις 27/07/2026 το lint debt ήταν 599. Καθαρίστηκαν 50 (τα συμπεριφορικά:
`jsx-key`, `static-components`, τυπογραφία). Απομένουν **549**, εκ των οποίων
**429 είναι `@typescript-eslint/no-explicit-any`** — δηλαδή το 78%.

## Η αιτία

`lib/supabase/client.ts` και `lib/supabase/server.ts` δημιουργούν τον client
**χωρίς παράμετρο τύπου σχήματος**:

```ts
return createBrowserClient(url, key)          // ← χωρίς <Database>
```

Χωρίς αυτήν, το `supabase.from('user_properties').select('*')` επιστρέφει
`any`. Κάθε πεδίο που διαβάζεται από τη βάση είναι `any`. Κάθε `.map()` πάνω
σε αποτέλεσμα ερωτήματος χρειάζεται `(x: any)`. Κάθε πρόσβαση σε στήλη που ο
TypeScript δεν ξέρει ότι υπάρχει χρειάζεται `(row as any).column`.

Δηλαδή: **οι 429 δηλώσεις `any` δεν είναι 429 ανεξάρτητες αβλεψίες. Είναι 429
συμπτώματα ενός σφάλματος ρύθμισης.**

Αυτό έχει άμεση πρακτική συνέπεια: αν κάποιος τις διόρθωνε μία-μία γράφοντας
χειροκίνητα interfaces, θα ξόδευε μέρες και το αποτέλεσμα θα ήταν **χειρότερο**
από το τίποτα — χειρόγραφοι τύποι αποκλίνουν σιωπηλά από το σχήμα με το πρώτο
migration και τότε ο TypeScript δίνει *ψεύτικη* ασφάλεια αντί για καθόλου.

## Η διόρθωση

Ένα βήμα, μία φορά και μετά συντηρείται μόνο του:

```bash
# 1. Παραγωγή τύπων από το ΠΡΑΓΜΑΤΙΚΟ σχήμα της βάσης
supabase gen types typescript --linked > lib/supabase/database.types.ts

# 2. Σύνδεση στους δύο clients
#    lib/supabase/client.ts:
#      import type { Database } from './database.types'
#      return createBrowserClient<Database>(url, key)
#    lib/supabase/server.ts:  το ίδιο, με createServerClient<Database>

# 3. Ο compiler δείχνει τώρα ΚΑΘΕ σημείο που ο τύπος ήταν λάθος.
#    Αυτό είναι το κέρδος, όχι ο αριθμός του lint.
npx tsc --noEmit

# 4. Αφαίρεση των casts που έγιναν περιττοί, ανά αρχείο, με το tsc οδηγό
```

**Γιατί δεν το έκανε ο agent:** το `--linked` απαιτεί `SUPABASE_ACCESS_TOKEN`.
Ο κανόνας αυτού του έργου είναι ότι το token δεν περνά ποτέ από συνομιλία ούτε
από περιβάλλον agent. Το βήμα 1 το τρέχει άνθρωπος, μία φορά.

## Τι κερδίζεται πραγματικά

Ο αριθμός του lint είναι το λιγότερο ενδιαφέρον μέρος. Τα ουσιαστικά:

- **Ένα migration που μετονομάζει στήλη σπάει το build, όχι την παραγωγή.**
  Σήμερα ένα `select('old_name')` μετά από μετονομασία περνά τον compiler
  καθαρά και γυρίζει `null` σε πραγματικό χρήστη.
- **Το `(row as any).share_percent` γίνεται ελεγμένο.** Υπάρχουν ήδη τέτοια
  casts σε οικονομικά πεδία (`BillsDashboard.tsx:453-455`) — δηλαδή σε ποσά.
- **Αυτόματη συμπλήρωση** για 100+ πίνακες, αντί για αναζήτηση στα migrations.

## Σειρά εφαρμογής

Μη γίνει σε ένα commit. Το βήμα 2 θα αναδείξει δεκάδες πραγματικές αποκλίσεις
τύπων ταυτόχρονα και ένα τεράστιο diff κρύβει τα σημαντικά.

1. Commit A: μόνο το `database.types.ts` (παραγόμενο, κανένας κώδικας δεν το χρησιμοποιεί)
2. Commit B: `<Database>` στους δύο clients + διόρθωση όσων σπάσουν στο `tsc`
3. Commits C…: αφαίρεση περιττών casts, **ανά αρχείο**, με τον ratchet να κατεβαίνει

Ο ratchet στο `scripts/lint-baseline.json` κατεβαίνει μετά από κάθε commit —
έτσι το κέρδος κλειδώνει και δεν μπορεί να επιστραφεί.
