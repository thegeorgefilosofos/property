What the existing guard misses

scripts/guard-dead-exports.mjs passes clean today (exit 0). It is a token counter, not a graph — for each export it counts \bNAME\b occurrences in other files and calls one hit alive. Five structural blind spots follow from that.

  1. A test import counts as a consumer. This is the big one: five entire modules and 366 exports are kept "alive" purely by the suite that tests them. Finding 1 is 776 lines the guard actively certifies as used.
  2. A re-export line counts as a consumer. export { tileGrid } from './tokens' in Theme.tsx is itself the occurrence that proves tileGrid alive — while nobody imports it from either file. The barrel launders its own contents.
  3. A comment counts as a consumer. The regex has no idea it is inside //. tileGrid is also named in a prose comment at components/tokens.ts:187.
  4. Name collisions count as consumers. cnt in supabase/functions/_shared/format.ts would read as alive off unrelated local variables named cnt in page.tsx and dynamicPricing.ts.
  5. Half the export syntax is invisible, and so are two directories. The pattern only matches ^export function and ^export const NAME[:=] — never export {…}, export … from, type, interface, class, or default. The glob covers app/ lib/ components/ only, so supabase/functions/, proxy.ts and scripts/ are unscanned in both directions.
